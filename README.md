# Токенизация данных (CourseProject)

## О проекте

**«Токенизация данных»** – это учебный проект, демонстрирующий, как можно безопасно хранить и получать пользовательские данные с использованием технологий блокчейна и шифрования. 

Цель проекта – предоставить пользователю возможность загрузить свои JSON-данные (например, персональные фитнес-данные), сохранить их в децентрализованном хранилище и блокчейне в зашифрованном виде, а затем при необходимости расшифровать и просмотреть эти данные. Таким образом обеспечивается **конфиденциальность** данных на публичном блокчейне: информация хранится открыто, но прочесть её может только владелец с соответствующим ключом шифрования.

Проект представляет собой веб-приложение, которое взаимодействует с Ethereum-блокчейном через MetaMask. Пользовательский интерфейс последовательно проводит through все этапы процесса и отображает результат на экране. Основные возможности приложения включают в себя:

- Подключение криптокошелька **MetaMask** для аутентификации и работы с блокчейном.
- **Загрузка JSON-данных** пользователя в распределённое файловое хранилище **IPFS** (InterPlanetary File System).
- **Шифрование** ссылки на файл (IPFS-хэша) с помощью симметричного ключа AES и шифрование самого ключа с использованием публичного ключа пользователя (Ethereum-ключа из MetaMask). Это двухуровневое шифрование гарантирует, что данные будут недоступны посторонним: даже хэш файла на IPFS хранится в блокчейне только в зашифрованном виде.
- **Сохранение** зашифрованного IPFS-хэша и зашифрованного AES-ключа в **смарт-контракте** на блокчейне Ethereum. Смарт-контракт выступает хранилищем метаданных: для каждого пользователя он сохраняет необходимые для восстановления данных значения.
- **Получение** данных обратно: контракт позволяет в любой момент извлечь зашифрованные значения. Приложение через MetaMask расшифровывает AES-ключ с помощью приватного ключа пользователя, затем расшифровывает IPFS-хэш и загружает исходный JSON с IPFS.
- **Отображение данных и результатов**: после успешного дешифрования JSON-данные пользователя выводятся на страницу. В проекте реализован модуль аналитики, который визуализирует содержимое данных – например, строит графики на основе загруженной информации. Это позволяет убедиться, что данные корректно восстановлены, и наглядно увидеть их содержание. Также интерфейс отображает ключевые этапы процесса (подключение кошелька, загрузка, шифрование, сохранение, расшифрование и т.д.), чтобы пользователь мог проследить шаги токенизации данных.

Таким образом, проект демонстрирует полный цикл работы: **от загрузки конфиденциальных данных до их безопасного хранения на блокчейне с последующим восстановлением и визуализацией**. Это полезно для случаев, когда требуется хранить личные данные (например, показатели физической активности, медицинские данные и т.п.) на публичных децентрализованных платформах, сохраняя их приватность.

## Используемые технологии

Проект объединяет сразу несколько современных технологий из области веб-разработки, блокчейна и защиты данных:

- **Frontend:** веб-интерфейс построен с использованием чистого HTML, CSS и JavaScript. Для визуализации данных используется библиотека **Chart.js**, позволяющая строить интерактивные диаграммы (например, радарные и столбчатые графики) по загруженным данным.
- **Блокчейн (Ethereum):** в качестве распределённого реестра применяется блокчейн Ethereum. Смарт-контракт, написанный на **Solidity**, деплоится локально с помощью фреймворка **Hardhat**. Для взаимодействия фронтенда с блокчейном используется библиотека **Ethers.js** совместно с кошельком **MetaMask**, что позволяет вызывать методы контракта напрямую из браузера.  
- **IPFS (InterPlanetary File System):** для децентрализованного хранения файлов JSON вне блокчейна проект задействует IPFS. С помощью SDK от **thirdweb** реализована загрузка файла на IPFS (`upload`) и последующая загрузка (`download`) при восстановлении данных.
- **Шифрование данных:** реализован гибридный подход к шифрованию. Симметричное шифрование выполняется алгоритмом **AES-256** (реализовано через библиотеку **CryptoJS**): на стороне клиента генерируется случайный AES-ключ, которым шифруется IPFS-хэш пользовательского файла. Далее для защиты самого AES-ключа используется асимметричное шифрование на основе **Ethereum-ключей** пользователя: публичный ключ, связанный с адресом MetaMask, полученный через провайдер Ethereum, применяется для шифрования AES-ключа (используется стандарт ECIES). Расшифрование выполняется соответственно с помощью приватного ключа Ethereum (через функцию `eth_decrypt` в MetaMask). Такой подход гарантирует, что только владелец соответствующего Ethereum-кошелька сможет восстановить исходные данные.
- **Thirdweb:** платформа **thirdweb** используется для упрощения интеграции Web3-функционала. В проекте thirdweb выступает в первую очередь для работы с IPFS (хранение файлов) и может использоваться для управления проектом через их сервис (потребуется ID клиента thirdweb). 
- **Инструменты разработки:** управление зависимостями и сборкой осуществляется с помощью **Yarn**. Код фронтенда бандлируется посредством **Webpack** (генерируется файл `bundle.js`), что позволяет запустить приложение в браузере без необходимости поднятия сервера Node.js. Для локального тестирования используется утилита **http-server** (запускает простой статический сервер для файлов проекта).

## Установка и запуск проекта локально

Чтобы запустить приложение локально и протестировать функциональность, выполните следующие шаги:

1. **Клонирование репозитория.** В терминале выполните команду:  
   ```bash
   git clone https://github.com/07kir09/CourseProject.git
   ```  
   Это склонирует проект в текущую директорию. Перейдите в папку проекта: `cd CourseProject`.

2. **Установка зависимостей.** Убедитесь, что у вас установлен Node.js. Затем выполните команду:  
   ```bash
   yarn install
   ```  
   Она установит все необходимые пакеты, указанные в `package.json` (включая Hardhat, Ethers, CryptoJS, thirdweb и др.).

3. **Запуск локального блокчейна.** Проект использует Hardhat для локальной сети Ethereum. Запустите ноду командой:  
   ```bash
   npx hardhat node
   ```  
   Эта команда поднимет локальный блокчейн на вашем компьютере. В консоли появится список тестовых Ethereum-адресов с балансом и их приватными ключами. Выберите первый адрес (или любой, который хотите использовать) и скопируйте его **приватный ключ**. Этот ключ необходимо сохранить в файле окружения, чтобы применять его для деплоя контракта:
   - Создайте в корне проекта файл **`.env`** (если он не был создан ранее).
   - Добавьте в `.env` переменную `WALLET_PRIVATE_KEY` и присвойте ей скопированный приватный ключ, например:  
     ```env
     WALLET_PRIVATE_KEY=0x123abc...789  (вставьте сюда ваш приватный ключ)
     ```  
   > **Примечание:** Hardhat-ноде будет открыта и работать в текущем терминале. Для выполнения следующих команд откройте новый терминал, не останавливая работу ноды (для остановки ноды нажмите **Ctrl+C**).

4. **Деплой смарт-контракта.** В новом терминале (в директории проекта) разверните контракт на запущенной локальной сети:  
   ```bash
   npx hardhat run scripts/Deploy.js --network localhost
   ```  
   В результате выполнения команды контракт сохранится в блокчейне Hardhat, а в консоли вы увидите адрес развёрнутого контракта (и, возможно, ABI контракта). Необходимо сконфигурировать фронтенд для работы с этим контрактом:
   - Откройте файл `.env` и добавьте переменную `CONTRACT_ADDRESS`, указав в качестве значения адрес вашего только что развернутого контракта. Например:  
     ```env
     CONTRACT_ADDRESS=0xABC123...DEF
     ```  
   - Также потребуется сообщить фронтенду ABI контракта. Откройте файл `main.js` (в корне проекта) и найдите в нём переменную или константу, предназначенную для ABI (например, `CONTRACT_ABI`). Замените содержимое этой переменной на фактический ABI вашего контракта. ABI – это JSON-описание интерфейса контракта, его можно скопировать из консоли вывода Hardhat (либо сгенерировать из исходника контракта). Убедитесь, что формат ABI корректный (массив JSON-объектов) и сохраните изменения в `main.js`.

5. **Настройка thirdweb.** Для работы с IPFS через thirdweb требуется ID клиента. Если у вас ещё нет аккаунта, зарегистрируйтесь на платформе thirdweb (https://thirdweb.com) и создайте новый проект, чтобы получить **Client ID**. После этого в файле `.env` добавьте переменную `THIRDWEB_CLIENT_ID`, присвоив ей полученный идентификатор:  
   ```env
   THIRDWEB_CLIENT_ID=<ваш client ID от thirdweb>
   ```  
   Thirdweb Client ID необходим приложению для использования сервисов thirdweb (например, хранения на IPFS) от вашего имени.

6. **Сборка бандла фронтенда.** Код JavaScript приложения необходимо собрать в единый файл, чтобы он мог выполняться в браузере. Выполните команду:  
   ```bash
   yarn run webpack
   ```  
   В результате в папке `dist` появится сгенерированный файл `bundle.js`, содержащий весь необходимый фронтенд-код (объединённый `main.js` и его зависимости). Этот файл уже подключён в `index.html`. **Важно:** каждый раз после внесения изменений в файлы фронтенда (например, `main.js`) необходимо повторно выполнять сборку через `webpack`, чтобы обновлять `bundle.js`.

7. **Запуск локального сервера и открытие приложения.** Последний шаг – запустить простой веб-сервер для отображения фронтенда. Используем установленный ранее **http-server**. В терминале выполните:  
   ```bash
   npx http-server
   ```  
   По умолчанию сервер раздаст содержимое текущей директории по адресу `http://127.0.0.1:8080` (точный адрес будет выведен в консоли). Откройте этот адрес в браузере. Вы должны увидеть веб-интерфейс приложения. Теперь можно взаимодействовать с ним:
   - В браузере подключите MetaMask к сайту (появится запрос на подключение аккаунта).
   - Загрузите JSON-данные (в проекте предусмотрен ввод или выбор файла JSON).
   - Следуйте инструкциям на экране для сохранения данных: по нажатию соответствующей кнопки произойдёт загрузка на IPFS, шифрование и сохранение в блокчейн (MetaMask запросит подтверждение транзакции).
   - Для проверки работы нажмите кнопку получения/расшифровки данных – приложение извлечёт данные из блокчейна, дешифрует их (MetaMask может запросить разрешение на расшифровку с вашим ключом), скачает файл с IPFS и отобразит исходные данные. На вкладке **Analytics** вы сможете увидеть визуализацию этих данных в виде графиков.

> **Примечание:** Если нужно остановить локальный блокчейн (Hardhat node) или сервер, нажмите в их терминалах комбинацию **Ctrl+C**.

## Мой вклад

В рамках данного проекта внёс вклад в следующие области:

- **Frontend-разработка:** разработка пользовательского интерфейса веб-приложения (HTML, CSS, JavaScript), интеграция MetaMask в браузере, обработка действий пользователя (загрузка файла, кнопки шифрования/дешифрования и т.д.), а также обеспечение взаимодействия фронтенда с back-end частями (вызовы смарт-контрактов, работа с API thirdweb).
- **Аналитика данных:** обработка загруженных JSON-данных для извлечения ключевой информации. В контексте проекта это включает парсинг данных (например, фитнес-метрик пользователя) и подготовку их для последующей визуализации (агрегация по дням, расчет необходимых показателей и т.п.).
- **Визуализация данных:** создание модуля визуализации на странице **Analytics**. Были реализованы графики (например, радарный график и гистограмма) с использованием библиотеки Chart.js, позволяющие наглядно представить загруженные пользователем данные. Это помогает лучше проанализировать восстановленные данные и подтвердить их целостность.
- **Частичная интеграция блокчейн-части с frontend:** участие в соединении фронтенда с блокчейном. В частности, реализация вызовов методов смарт-контракта из JavaScript через Ethers.js, обработка ответов (например, получение зашифрованных данных из контракта), а также использование возможностей MetaMask для шифрования/дешифрования сообщений (получение публичного ключа, вызов функций шифрования и расшифровки). Этот вклад обеспечил корректную работу цепочки: фронтенд → MetaMask → смарт-контракт → обратно, связывая все компоненты проекта воедино.

Соединяя все эти части, проект **«Токенизация данных»** служит отличным примером междисциплинарной разработки, где на стыке frontend и blockchain-решений достигается новая функциональность – безопасная токенизация пользовательских данных.
